For decades, software projects have accepted dozens of PRs, weak test coverage, functional testing only at release time, and rare performance checks. The same often applies to dependencies, including immature libraries. Even without AI, this creates bugs and vulnerabilities. AI amplifies and accelerates the same pattern.

Better prompts and reviews help, but they are not enough. The balance to fix is between product quality and the price customers are asked to pay. Products that care about quality do exist, but they are still too rare.

When AI is added, specific models matter. A large general model has been trained on a vast amount of code, much of it similar to the average project described above. No one has verified that all those sources are well designed, bug-free, and secure. Poor code from AI should not surprise us.

A coding model trained on high-quality material is a step forward, but the model is not the whole system. Software tools were built for humans, not for a fast machine. We need tools that can assess AI output at the same speed.

AI can create a full test environment, run checks, and release resources in minutes for every change. Without this kind of automation, AI in software development may become a failure.
